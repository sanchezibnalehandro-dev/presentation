# HTML MVP: два экрана без изобретения собственного PowerPoint

## Назначение

Одно браузерное приложение, **два окна на одном ноутбуке** в режиме Windows «Расширить»:

| Экран ведущего | Экран аудитории |
| --- | --- |
| Текущий слайд | Только текущий слайд |
| Миниатюра следующего | Вписанный в 16:9 без обрезания текста |
| Полные заметки конкретного слайда | Никаких заметок, номеров, таймеров или панелей |
| Время выступления и ориентир по таймингу | Внешние ссылки/живые демонстрации по отдельной команде |
| Кнопки «назад / вперёд / выбрать слайд» | Полноэкранный показ |
| Возможность скроллить сценарий независимо | Нет прокрутки страницы |

## Минимальная архитектура

**Статика, без сборщика и без backend:** HTML + CSS + JavaScript + JSON-манифест. Для пятислайдового прототипа можно пользоваться нативными API; если Reveal.js оказывается действительно удобнее, подключить его с фиксированной версией и локальными файлами. Не превращать выбор библиотеки в отдельный проект.

- `presenter.html` — панель ведущего; единственный источник команд.
- `audience.html` — экран аудитории, только чтение.
- `data/slides.json` — порядок, идентификаторы, источники и отображаемые заголовки.
- `assets/slides/01.png` … `25.png` — локальные экспортированные изображения для офлайн-режима (**сейчас ещё не внесены в репозиторий**).
- `content/notes.json` или Markdown — текстовые заметки, отделённые от PNG.

**Синхронизация:** для двух окон на одном origin использовать `BroadcastChannel`, при открытии нового окна запрашивать текущий слайд; состояние хранить локально для обновления окна. Не нужны внешние веб-сокеты или сервер только для переключения слайдов.

## UX и управление

- Кнопка «Открыть экран аудитории» вызывает отдельное окно по клику (чтобы браузер не заблокировал попап).
- Проектор подключён в режиме расширенного рабочего стола; окно аудитории переносится туда и разворачивается в full-screen вручную.
- Стрелки, Space/PageDown и кнопки меняют слайд **только когда курсор не в поле ввода**.
- Экран аудитории слушает сообщения, но не принимает собственные команды переключения.
- Сразу видно номер 01/25, текущий и следующий кадр, прошедшие минуты, ориентир по сценарию.
- Сценарий читается без мелкого шрифта: регулируемый размер текста и отдельная прокрутка.
- При перезагрузке окна корректно восстанавливается текущая позиция.
- Необходимо явно показать состояние подключения экрана аудитории и позволить повторно открыть его.
- Слайды должны подгоняться целиком (`object-fit: contain`), не обрезая текст.

## Первое проверяемое вертикальное сечение

**Только 01–05**, но на настоящих картинках:

1. Открыть presenter.
2. Кнопкой открыть audience и вывести на второй монитор.
3. Переключить 01 → 02 → 03; проверить синхронизацию.
4. Вернуться на 02; после reload состояние должно восстановиться.
5. Прокрутить длинные заметки, не меняя слайд у аудитории.
6. Прогнать 5 минут как настоящее выступление, оценить удобство панели.

Лишь затем добавлять 06–25, QR, внешние демонстрации и прочее.

## Офлайн и развертывание

Режим offline **не существует автоматически**: оба HTML-файла и 25 картинок должны быть на одной локальной машине; внешние CDN исключить. Работу `BroadcastChannel` проверять на одном origin через локальный HTTP сервер (`python -m http.server` — пример для теста), а не полагаться на `file://` с разными origin.

Внешние Q&A/сайты требуют интернета. PPTX/PDF — резерв.
