# COURSE STUDIO V2 — решение, архитектура, контроль качества

Статус: реализация в ветке \`feature/course-production-studio\`. Владелец: производство курса «ChatGPT для маркетинга». Дата решения: 2026-11-03.

## Почему делаем апгрейд
Визуалы NotebookLM/PPTX/PDF значительно содержательнее старых HTML-карточек. Цель: использовать уже созданное изображение **без потери композиции**, сохраняя суфлёр, синхронизацию и режиссуру. Для текущего урока получен PDF 12 страниц с иллюстрациями «факт/гипотеза/неизвестно», диаграммой симптом/причина и диагностической картой.

## Архитектура
- \`course-studio/index.html\` — пульт ведущего; sole source of navigation.
- \`studio.js\` — текущий урок, текущий кадр, заметки и локальная привязка File.
- \`frame.js\` — общий безопасный renderer для preview и viewer; image/HTML/live/blackout.
- \`viewer.html\`+\`viewer.js\` — зрительское окно; только whitelisted \`visual\`, без речи и заметок.
- \`tools/prepare_deck.py\` — офлайн конвертация PDF/PPTX в 1920px PNG и JSON.
- \`tools/check-deck.mjs\` — сверка ссылок на локальные картинки, структуры и читаемости разрешения.

## Контракт безопасности
1. Публичный GitHub: только код, схемы и демонстрационные данные; \`private-decks/\` игнорируется.
2. \`viewer\` получает \`postMessage\` от того же \`origin\` и \`window.opener\`.
3. Через message передаём только \`visual\`, \`blackout\`, и, если требуется, сам \`File\` изображения.
4. Локальные ассеты: только относительные пути без \`../\`, протоколов \`http(s)\`, \`data\` и javascript.
5. sessionStorage содержит текст последнего JSON в вкладке ведущего. Он не является сейфом. Для чувствительных данных использовать синтетические примеры.
6. Никаких автоматических сетевых запросов PDF-конвертера или сервера студии; локальный сервер нужен только для статических файлов.

## Соглашение о двух способах импорта
- **Быстрый:** select multiple image/png/jpeg/webp. При совпадении числа image-кадров — привязка по натуральной сортировке имён. Не переживает reload, необходимо импортировать заново.
- **Воспроизводимый:** PDF/PPTX → \`tools/prepare_deck.py\` → \`private-decks/<slug>/slide-NNN.png\` и \`deck.json\` → импорт JSON. Переживает reload, если файлы не перемещены. Для синхронизации с текстом урока использовать внешний private JSON с теми же src. Конвертер не пишет сюда полный платный сценарий.

## Что в кадре
- Image (обычно): оригинальная качественная графика; fit contain.
- Live (демонстрация): титр перехода, затем оператор **в OBS** показывает реальный сервис. Автопереключения OBS пока нет.
- HTML (вспомогательно): титры, краткие алгоритмы, проверочные вопросы.
- Blackout: ручной режим приватности при смене сцены.

## Не делаем в v2
- Переписывание исходной «Неандертальцы» презентации и её PNG.
- Хранение исходного платного материала в публичной ветке.
- Редактирование PPTX внутри браузера.
- Самостоятельная запись OBS, вход в ChatGPT или доступ к закрытым аккаунтам.
- Сложный backend/логины/развертывание платформы.

## Дополнение безопасности: локальный сервер

Команда записи должна использовать `py -m http.server 8000 --bind 127.0.0.1`. Python http.server без bind обычно слушает все сетевые интерфейсы и может непреднамеренно раскрыть `private-decks` устройствам в локальной сети. Это особенно важно для приватного платного контента. Если требуется удалённая трансляция, используйте OBS, а не общий доступ к папке. При экспорте PPTX через LibreOffice возможны изменения шрифтов; до записи сверить изображения со слайдами исходного PowerPoint.

Устранена ссылка на README.md, показывавшая в Firefox сырой Markdown с ошибочным отображением кириллицы: теперь кнопка «PDF/PPTX · помощь» открывает читаемый HTML-диалог внутри студии. Техническая конвертация в браузере не заявляется. Добавлено перетаскивание разделителя колонок, управление клавишами и сохранение ширины. Область речи speech[] отделена от фиксированной нижней панели action; production и check перестали выводиться в UI, при этом JSON остаётся обратно совместимым. ## Запуск одним действием (v2.2)

На Windows из корня репозитория доступен `START_COURSE_STUDIO.cmd`, который запускает `course-studio/tools/launch_studio.py`. Python-скрипт использует стандартную библиотеку, проверяет, что на порту работает именно Course Studio, повторно использует существующий сервер, при занятом порте 8000 выбирает свободный в диапазоне 8000–8010, поднимает HTTP-сервер исключительно на loopback и открывает браузер. В случае отсутствия Python или занятости всех портов сообщает об ошибке. Не строить отдельный Electron/Tauri-продукт для этой простой задачи.

Граница безопасности: никаких `--bind 0.0.0.0` и внешнего хостинга приватных слайдов. Логи создаются в локальном профиле пользователя, вне GitHub. Приёмка: двойной клик Windows, повторный двойной клик без нового сервера, порт 8000 занят другой программой, запуск из произвольной рабочей папки, открытие правильного адреса.
